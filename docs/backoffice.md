# 백오피스 — 정책과 기획

> 결정 원본: `docs/project.md` D-32. 화면·API는 이 문서가 기준이고, 계약 표는 `docs/architecture.md §3`이 원본이다.
> 마지막 갱신: 2026-09-17

## 1. 무엇이고, 무엇이 아닌가

**요고비 운영자가 쓰는 관리 화면이다.** 두 가지만 한다.

| 축 | 하는 일 | 화면 |
|---|---|---|
| ① 사용 지표 | 회원·세션·카탈로그·검수·제보 현황을 한 화면에서 본다 | `/admin` 상단 |
| ② 수집 데이터 검수 | 매일 09:00(KST) 모은 변경 후보를 승인·거절한다 | `/admin` 중단 |
| ③ 변경 이력 | 누가 언제 무엇을 바꿨는지 본다(D-26·D-27). 되돌린 변경(`FAILED`)도 남는다 | `/admin` 하단 |

**아닌 것** — 아래는 의도적으로 넣지 않았다.
- **별도 서버·레포가 아니다.** 사용자 결정이다. 관리 화면은 프론트 앱의 `/admin` 라우트
  (`front/src/pages/Admin.jsx`, D-39)이고 기능은 전부 BE API다. 레포·배포 앱·인증 체계를 하나 더 늘리지 않는다
  (D-25의 판단을 그대로 유지). 2026-09-17 전까지는 BE가 `admin.html`·`admin.js`를 정적으로 내려줬다.
- **회원 관리 도구가 아니다.** 회원 목록 열람·수정·탈퇴 처리 기능은 없다. 개인정보 접근면을 넓히지 않는다
  (`docs/privacy.md`). 지표는 **집계 숫자만** 본다.
- **분석 도구가 아니다.** 화면 단위 이탈율·퍼널은 브라우저 이벤트를 수집하지 않아 낼 수 없다(D-25 한계 그대로).
  Fly 관리형 그라파나는 그대로 쓴다 — 이 화면이 그것을 대체하지 않는다.

## 2. 접근 권한

```
ADMIN_ID / ADMIN_PASSWORD  →  app_user 행(부트스트랩)  →  ROLE_ADMIN  →  /api/v1/admin/**
```

- **설정이 원본이다.** 시작할 때 설정값으로 관리자 계정을 만들거나 갱신한다. 비밀번호가 바뀌면
  기존 관리자 세션을 **전부 무효화**한다(`credential_version` 증가).
- **설정이 비면 백오피스는 잠긴다.** 관리자 계정을 만들지 않고 로그인도 되지 않는다. 기본값은 잠금이다.
- 로그인은 **아이디**로 한다(회원 로그인은 이메일 형식을 요구하므로 경로가 다르다). 세션·쿠키·JWT·CSRF는
  회원과 **같은 장치**를 쓴다 — 인증 체계를 두 벌 만들지 않는다.
- 실패 응답은 회원 로그인과 같은 `401 YGB-AUTH-001` 하나다. 아이디 존재 여부를 구분해 알리지 않으며,
  같은 아이디에 대한 시도 횟수를 제한한다.
- 관리자 계정은 `CATALOG_ADMIN_USER_IDS`에 없어도 운영자다(D-24 권한을 그대로 물려받는다).
- `/admin` 화면은 누구나 열 수 있지만 **데이터는 전부 인증이 필요**하다.
  화면만 열리고 아무 숫자도 보이지 않는다. 검색엔진 색인은 프론트 nginx 의 `X-Robots-Tag: noindex`로 막는다.

> ⚠️ **운영 전 반드시 바꿀 것**: 데모용으로 짧은 비밀번호를 쓰고 있다. 운영 배포에서는 긴 임의 문자열로 교체한다.
> 값은 `.env`·배포 secret에만 두고 레포에 적지 않는다.

## 3. 축 ① 사용 지표

`GET /api/v1/admin/dashboard`. **DB에 기록이 있는 것만 낸다** — 없는 숫자를 만들지 않는다.

| 묶음 | 항목 |
|---|---|
| `members` | 전체 회원 · 24시간 가입 · 7일 가입 · 구독 등록 회원 · 활성 세션 |
| `activity` | 최근 **14일** 일별 활동 — 가입·제보·수집 제안·카탈로그 반영 (없는 날도 0으로 채운다). 퍼널과 시간축이 같다 |
| `weeklyActivity` | `activity` 의 뒤 7일. **배포된 화면이 쓰는 옛 키**이고, 화면이 옮겨 가면 지운다 |
| `funnel` | 게이트 퍼널 14일 — 횟수·사람 수·전환율·종류별 마지막 적재일·날짜 기준 (아래) |
| `kpi` | 최종보고서 §9.2 핵심 KPI 3종 (아래) |
| `savings` | 찾아 준 절감액 — 중앙값·평균·합계·분포·월 5,000원 이상 인원(`opportunity`) |
| `catalog` | 요금제 · 구독 서비스 · 구독 등급 · 제휴 혜택 수(활성 기준) |
| `review` | 검수 대기 · 불일치(차단) · 미확인 · 24시간 내 반영 |
| `reports` | 정보 오류 제보 대기·전체 |
| `gaps` | 카탈로그 결손(`catalog_candidate` REQUESTED) |
| `endpoints` | 요청 상위 8개 경로의 요청수·평균 지연 |

- 지표는 상단 KPI 4줄(`KPI`)과 묶음별 카드 11개(`CARDS`) 합쳐 **15개**다. `members.signedUp24h`는
  전체 회원 옆 증감 배지로 붙는다. 늘어나면 `front/src/pages/Admin.jsx`의 `KPI`·`CARDS`에 줄을 더한다.
- 값이 `-1`이면 **"알 수 없음"** 이다(표가 없거나 조회 실패). 화면은 `—`로 보여준다 — 0으로 표시하면 거짓말이 된다.
- `endpoints`는 micrometer 레지스트리에서 읽으므로 **프로세스 재시작 시 0부터** 다시 센다. 화면에 그렇게 적는다.

### 퍼널 (`funnel`) — 세는 규칙이 셋이다

| 열 | 뜻 |
|---|---|
| `gateShown`·`reportShown`·`memberLogin` | **횟수**(`funnel_daily`). `contaminatedUntil` 까지는 결과 화면 무한 호출로 부풀어 있다 |
| `unique` | **창 전체의 사람 수**(`funnel_event`, `actor_key` 중복 제거). 일별 값의 합이 아니다 — 사흘 들른 한 사람은 1 이다(G-56) |
| `uniqueDaily` | 일별 사람 수. 이걸 더하면 사람-일이 되므로 `unique` 와 다르다 |
| `conversion` | 백분율. **같은 행위자가 두 단계를 다 밟았는지**로 낸다. `gateToLogin` 은 비회원 `ip:`·회원 `u:` 라 이을 수 없어 **항상 null**. 모수 0 도 null — 0% 는 "다 이탈했다"는 뜻이라 거짓이 된다 |
| `lastSeen` | 종류별 **마지막으로 쌓인 날**. 한 번도 없으면 `null` 이고 **키는 사라지지 않는다** |
| `dateBasis` | 날짜를 어느 시간대로 잘랐는지. 세션에서 읽어 내므로 설정과 어긋날 수 없다(D-63) |

`lastSeen` 이 있는 이유: 집계 실패는 삼켜진다(기능이 지표 때문에 멈추면 안 된다). 그 대가로 화면에서
**"아무도 안 했다"와 "못 세고 있다"가 같아 보인다.** 실제로 `funnel_daily` 의 CHECK 때문에
`CALENDAR_SHOWN`·`RESULT_SAVED` 가 2026-09-18~21 사흘 동안 통째로 안 쌓였는데 그렇게 보였다(V31).
표를 `GROUP BY` 로만 읽으면 행이 없는 종류가 결과에서 사라지므로 `FunnelCounter.ALL` 기준으로
좌외부조인한다 — **행이 없는 것 자체가 화면에 뜬다.**

"며칠 이상이면 경고"는 정하지 않았다. 단계마다 정상 빈도가 달라 한 숫자로 못 자른다
(저장은 원래 드물고 게이트는 매일 온다).

### 핵심 KPI (`kpi`) — 최종보고서 §9.2

| 항목 | 정의 | 상태 |
|---|---|---|
| `resultReachRate` | 결과 화면 도달 ÷ **입력 시작** 사용자 | ✅ 낸다. 분자는 게이트(`ip:`)·리포트(`u:`) 양쪽을 센다(G-59) |
| `calcErrorRate` | 정답셋 불일치 ÷ 검산 건수 | ❌ **런타임 값이 아니다.** 배포 전 골든 감사 결과라 대시보드가 낼 숫자가 아니다 |
| `savingOpportunityRate` | 월 **5,000원 이상** 순절감 가능 ÷ 유효 계산 회원 | ✅ 낸다. 분모는 `member_savings` 행이 있는 회원 — 지금 요금제를 모르면 비교가 성립하지 않아 빠진다 |

**못 내는 칸은 키를 지우지 않는다.** 키가 없으면 화면이 "아직 안 만들었나"로 읽고, 0 을 넣으면
거짓이 된다. `null` + `*Note`(이유)로 낸다. **값이 있으면 `*Note` 를 보내지 않는다** — 값과 이유가
동시에 있으면 둘 중 하나가 반드시 낡는다(실제로 그렇게 어긋났다, 2026-09-21).

입력 단계는 서버가 볼 수 없어 화면이 `POST /api/v1/events` 로 알려 준다(D-62). 받는 종류는
`INPUT_STARTED`·`INPUT_COMPLETED` 뿐이고 **서버가 관측하는 다섯은 받지 않는다** — 받게 하면
요청 한 번으로 리포트 조회 수를 부풀릴 수 있다.

## 4. 축 ② 수집 데이터 검수

### 흐름

```
매일 09:00 KST  CatalogDailyHarvest
   └─ 요금제: smartchoice_plan_snapshot 과 mobile_plan.base_price 비교
      (구독 등급은 대조 소스가 없어 수집하지 않는다 — D-45)
        ↓ 다른 것만
   변경 제안(PENDING)  ──자동검토(D-29·D-35)──  VERIFIED / MISMATCH / UNVERIFIED / SKIPPED
        대조 소스: 스마트초이스 시세 · 통신사 공식 목록 (모델 안 씀, D-45)
        ↓ 운영자가 화면에서
   승인 → 합본 CSV + DB 반영 + 감사 기록   |   거절 → 사유와 함께 종결
```

**수집은 절대 바로 반영하지 않는다.** 제안만 만든다. 그래야 자동검토(D-29)와 승인 절차(D-28)를 그대로 탄다.

### 규칙

- **±100원 이내 차이는 제안하지 않는다.** 표기 반올림으로 매일 같은 줄이 쌓이면 검수함이 못 쓰게 된다.
- **같은 대상의 PENDING 제안이 있으면 또 만들지 않는다.**
- **한 번에 만드는 제안 수를 제한한다**(요금제 20 · 구독 10, 설정으로 조절). 소스가 흔들린 날
  수백 건이 쌓이면 아무도 검수하지 않는다. 상한에 걸려 빠진 항목은 다음 실행에서 다시 후보가 된다.
- **`MISMATCH`는 승인할 수 없다**(서버 409, 화면에서도 버튼 비활성). `UNVERIFIED`는 승인할 수 있다 —
  어느 소스도 확인하지 못한 것뿐이며, 틀렸다는 뜻이 아니다. 놓친 오류는 사용자 제보로 잡는다(D-18).
- 수집 실패는 카탈로그를 건드리지 않는다. 다음 날 다시 돈다.
- 급할 때는 화면의 **"② 지금 수집 실행"**(`POST /api/v1/admin/harvest/run`)으로 즉시 한 번 돌린다.
- **스냅샷이 비어 있으면 요금제 제안이 안 나온다.** 먼저 **"① 시세 스냅샷 수집"**
  (`POST /api/v1/admin/smartchoice/sweep`)을 돌린다. 결과는 셋으로 갈린다 —
  키 없음(`enabled:false`) / 서버에 못 닿음(`reachable:false`, 등록 IP·접속 국가 제한 가능) / 정상.
- ⚠️ **배포 머신이 유휴 시 정지(`auto_stop_machines`)라 예약 시각에 잠들어 있으면 스케줄이 발화하지 않는다.**
  스마트초이스 스윕·일일 수집·환율 갱신·개인정보 파기가 모두 해당한다. 그래서 이 수동 경로가 실질적인 실행 수단이다.
  상시 가동이 필요하면 `min_machines_running = 1` 로 바꿔야 한다(비용 발생, 별도 결정).

### 외부 호출 경계

외부(스마트초이스·AI) 호출은 **이 배치와 승인 절차에서만** 일어난다.
사용자 요청 경로는 여전히 외부를 부르지 않는다(D-05·D-17 유지).

## 5. API

| Method | Path | 설명 |
|---|---|---|
| POST | `/api/v1/admin/login` | 아이디·비밀번호 로그인(공개). 실패는 401 하나 |
| GET | `/api/v1/admin/session` | 관리자인지 확인 |
| GET | `/api/v1/admin/dashboard` | 축 ① 지표 |
| GET | `/api/v1/admin/reports` | **제보 게시판** — `catalog_report`+`service_report` 합본 최신순. `?status=PENDING` · `?limit=`(기본 50·최대 200). **제보자 회원 신원은 싣지 않는다**(D-42) |
| PATCH | `/api/v1/admin/reports/{kind}/{id}` | 처리 상태 변경(`PENDING`·`RESOLVED`·`REJECTED`). `kind` 는 `CATALOG`·`SERVICE`. **원본 카탈로그는 바뀌지 않는다** — 가격 수정은 D-28 승인을 따로 탄다 |
| POST | `/api/v1/admin/harvest/run` | 축 ② 수집 즉시 실행 |
| POST | `/api/v1/admin/smartchoice/sweep` | 시세 스냅샷 즉시 수집. 수집(②)보다 **먼저** 돌려야 한다 |
| GET | `/api/v1/admin/catalog/requests` | 검수 목록(`?status=PENDING` 등) |
| POST | `/api/v1/admin/catalog/requests/{id}/approve` `/reject` | 승인 · 거절 |
| GET | `/api/v1/admin/catalog/audit` | 변경 이력(D-27) |

로그아웃은 회원과 같은 `POST /api/v1/auth/logout`을 쓴다. 변경 요청에는 CSRF 헤더가 필요하다.


## 7. 아직 없는 것

- **알림이 없다.** 검수 대기가 쌓여도 아무도 알려주지 않는다. 운영자가 화면을 열어야 안다.
- **수집 소스가 좁다.** 검토 대조는 두 곳(스마트초이스 · 통신사 공식 목록)이고,
  통신사 공식 어댑터는 SK세븐모바일·LG헬로모바일·KT엠모바일·U+유모바일 넷이라 521행을 덮는다.
  나머지 사업자는 스마트초이스 한 곳으로만 대조한다.
- **구독 등급은 갱신도 검토도 못 한다(D-45).** 대조 소스가 모델뿐이었다. 가격이 바뀌어도 알 수 없고
  사용자 제보로만 잡힌다. 서비스별 공식 페이지 어댑터를 붙이면 되살아난다.
  제휴 혜택·번들은 대조 소스가 없어 수집·검토 대상이 아니다.
- ~~제보 처리 화면이 없다~~ → **생겼다**(2026-09-17). `/api/v1/admin/reports` 로 두 표를 한 목록에서 보고
  상태를 바꾼다. 다만 **상태만 바뀐다** — 제보를 읽고 가격을 고치는 것은 여전히 D-28 승인 경로다.
  제보 본문에서 변경 제안을 자동 생성하지는 않는다.
- **회원 단위 조회가 없다.** 넣으려면 개인정보 처리방침·접근 통제를 먼저 정해야 한다.
